6. What is the month-over-month revenue growth rate?
SQL QUERY:
WITH monthly_revenue AS (
    SELECT d.year, d.month_name AS month, d.month AS month_num,
           SUM(oi.total_revenue) AS revenue
    FROM dim_date d
    JOIN fact_orders o ON d.date_id = o.order_date
    INNER JOIN fact_order_items oi ON o.order_id = oi.order_id
    GROUP BY d.year, d.month_name, d.month
),
lagged AS (
    SELECT year, month, month_num, revenue,
           LAG(revenue) OVER (ORDER BY year, month_num) AS prev_month_revenue
    FROM monthly_revenue
)
SELECT year, month, revenue,
       ROUND((revenue - prev_month_revenue) / prev_month_revenue * 100, 2) AS mom_growth_pct
FROM lagged
ORDER BY year, month_num; 

Insights: Revenue follows a clear seasonal pattern across all four years, Q4 (November–December) consistently peaks while January records the sharpest drop each year, 
falling between -42% and -48% from the December high. Growth is generally stable through mid-year before the festive surge kicks in.

Recommendations: Build a January recovery strategy through post-festive promotions and loyalty campaigns to cushion the annual revenue drop. Front-load inventory and 
marketing investment ahead of Q4 every year to maximise the predictable festive surge.

 whether through survey data or purchase pattern analysis would further sharpen the retention strategy.


16. RFM Segmentation — Score each customer on Recency, Frequency, and Monetary value.
SQL QUERY
WITH rfm_base AS (
    SELECT 
        dc.customer_id,
        dc.customer_name,
        DATEDIFF(MAX(fo.order_date), '2024-12-30') * -1 AS recency_days,
        COUNT(DISTINCT fo.order_id) AS frequency,
        SUM(oi.total_revenue) AS monetary
    FROM dim_customer dc
    INNER JOIN fact_orders fo ON dc.customer_id = fo.customer_id
    INNER JOIN fact_order_items oi ON fo.order_id = oi.order_id
    GROUP BY dc.customer_id, dc.customer_name
),
rfm_scored AS (
    SELECT *,
        NTILE(3) OVER (ORDER BY recency_days ASC) AS r_score,
        NTILE(3) OVER (ORDER BY frequency DESC) AS f_score,
        NTILE(3) OVER (ORDER BY monetary DESC) AS m_score
    FROM rfm_base
)
SELECT 
    customer_id,
    customer_name,
    recency_days,
    frequency,
    monetary,
    r_score,
    f_score,
    m_score,
    CASE 
        WHEN r_score = 3 AND f_score = 3 AND m_score = 3 THEN 'Champion'
        WHEN r_score >= 2 AND f_score >= 2 THEN 'Loyal Customer'
        WHEN r_score = 3 AND f_score = 1 THEN 'New Customer'
        WHEN r_score = 1 AND f_score >= 2 THEN 'At Risk'
        ELSE 'Needs Attention'
    END AS rfm_segment
FROM rfm_scored
ORDER BY monetary DESC;

Insights
The RFM segmentation reveals a healthy mix of customer types, Champions cluster around high monetary scores regardless of frequency, while At Risk customers show high 
recency scores but low frequency, suggesting they were once active but have gone quiet. The majority fall into Needs Attention, consistent with the 11.9% single-purchase 
finding from Q15.

Recommendations
Prioritise Champions for exclusive loyalty rewards to protect NovaMart's highest-value relationships. At Risk customers need immediate win-back campaigns, they've 
purchased before so the barrier to re-engagement is lower than acquiring new customers. Needs Attention customers represent the largest opportunity volume-wise and 
should receive automated re-engagement sequences.

24. For each product category, show the running total of revenue over time.
SQL QUERY
SELECT
    p.category,
    d.full_date,
    ROUND(SUM(f.total_revenue), 2) AS daily_revenue,
    ROUND(SUM(SUM(f.total_revenue)) OVER (
        PARTITION BY p.category
        ORDER BY d.full_date
    ), 2) AS running_total
FROM fact_order_items f
INNER JOIN fact_orders o ON o.order_id = f.order_id
JOIN dim_product p ON f.product_id = p.product_id
JOIN dim_date d ON o.order_date = d.full_date
GROUP BY p.category, d.full_date
ORDER BY p.category, d.full_date;

Insight
All categories show a steady, uninterrupted upward running total across the dataset period, no visible plateaus or reversals confirming consistent sales activity 
throughout. Daily revenue fluctuates normally but the cumulative trend is stable across Beauty, Books, Electronics, Fashion, Grocery, Home & Living and Sports.

Recommendation
Use the running total as a baseline to layer in seasonality analysis, identifying which months accelerate the curve most steeply per category will inform where to 
concentrate promotional spend ahead of naturally high-demand periods.

26. Cohort Analysis: Group customers by their first purchase month and track how many returned in subsequent months.
SQL QUERY
SELECT
    cohort_month,
    months_since_first_purchase,
    COUNT(DISTINCT customer_id) AS returning_customers
FROM (
    SELECT
        o.customer_id,
        DATE_FORMAT(MIN(o.order_date) OVER (PARTITION BY o.customer_id), '%Y-%m') AS cohort_month,
        TIMESTAMPDIFF(
            MONTH,
            MIN(o.order_date) OVER (PARTITION BY o.customer_id),
            o.order_date
        ) AS months_since_first_purchase
    FROM fact_orders o
) cohort_data
GROUP BY cohort_month, months_since_first_purchase
ORDER BY cohort_month, months_since_first_purchase;

Insight
The January 2021 cohort i.e NovaMart's earliest customers shows 631 first-time buyers, with returning customer counts staying relatively stable in the 20–47 range 
across subsequent months. Later cohorts like 2024-11 and 2024-12 show only month-0 activity, which is expected as they haven't had time to return yet. Retention does 
not collapse sharply, suggesting reasonable but not exceptional repeat purchase behaviour.

Recommendation
Focus retention investment on months 1–3 post-acquisition where the drop from 631 to the 20–47 range is steepest. A structured onboarding sequence such as follow-up 
offers, personalised recommendations in the first 90 days could meaningfully lift those early return figures across all cohorts.

27. What is the revenue contribution of flagged outlier rows vs clean rows?
SQL QUERY
SELECT
    CASE
        WHEN outlier_flag = 'Yes' THEN 'Flagged Outlier'
        ELSE 'Clean'
    END AS row_type,
    COUNT(item_id) AS total_rows,
    ROUND(SUM(total_revenue), 2) AS total_revenue,
    ROUND(SUM(total_revenue) / SUM(SUM(total_revenue)) OVER () * 100, 2) AS revenue_pct
FROM fact_order_items
GROUP BY outlier_flag;

Insight
100% of revenue with ₦14.51B across 96,189 rows is attributed to clean rows, with zero flagged outlier contribution. This is consistent with the Q25 finding and points 
to the same root cause: the outlier_flag value in the database does not match 'Yes' exactly. The cleaning work was done, but the flag values need verification before 
this query returns a meaningful split.

Recommendation
Once the correct flag value is confirmed and the query is adjusted, this result will be analytically significant it will quantify exactly how much revenue would have 
been distorted had outlier rows been left uncapped, directly validating the cleaning decisions made during the Excel stage.
